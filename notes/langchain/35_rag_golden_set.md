# RAG Golden Set

## RAG Golden Set 요약
RAG Golden Set은 RAG 평가 기준이 되는 질문·기준 답변·원문 근거 모음이다. 이 노트북은 코드 없이 Golden Set을 설계·작성·검수·버전 관리하고 평가에 연결하는 방법을 정리한 가이드다.
- 흐름: 평가 범위 정하기 → 원문·근거 선택 → 질문·기준 답변 작성 → 검수 → 버전 관리·저장

## RAG Golden Set이란
RAG Golden Set은 "이 질문에는 이 문서의 이 근거로 이런 내용을 답해야 한다"를 미리 확정해 둔 평가용 정답 모음이다. 어떤 사용자의 질문을 다룰지, 어떤 문서와 버전을 기준으로 답할지 먼저 정한다. 답변 가능한 문항의 근거는 반드시 검색 대상 문서에 있어야 하고, 문서 버전도 평가 대상과 같아야 한다. 평가 대상 원문은 제목, 본문, 출처, 버전을 기록해 준비한다.

## RAG Golden Set 문항 필수 항목
RAG Golden Set 문항마다 작성하는 항목 예시다(평가 목적·도구에 맞게 조정).
- 질문: RAG에 넣을 사용자 질문
- 기준 답변: 반드시 들어가야 할 핵심 내용과 조건. 평가할 RAG의 출력이 아니라 원문 검수로 확정한 비교 기준이다.
- 관련 문서: 파일명·URL·문서 ID. 검색기가 필요한 문서를 가져왔는지 확인용.
- 근거 구절: 기준 답변을 뒷받침하는 원문 그대로의 인용. 검색 청크에 실제 근거가 있는지 확인용.
- 근거 위치: 페이지·절·조항. 청크 구성이 바뀌어도 같은 근거를 추적한다.
- 답변 가능 여부: 원문 전체로 답할 수 있는지. 검색 실패와 원문에 답이 없는 경우를 구분한다.
- 질문 유형: 사실 확인, 조건 비교, 답변 불가 등. 유형 편중을 막고 유형별 약점을 본다.

기준 답변은 문장을 고정하는 게 아니라 포함할 내용을 정하는 것이다. 문항 ID와 평가셋 버전도 함께 관리한다.

## RAG Golden Set 선택 항목과 정답 단위
RAG Golden Set에서 결과를 자료 형태나 질문 특성별로 나눠 보고 싶을 때 선택적으로 추가하는 항목이다.
- 근거 형태: 본문, 표, 이미지·도표, 혼합. 어떤 형태에서 검색·이해가 약한지 본다.
- 난이도: 필요한 정보 수, 조건·예외 해석, 근거 종합 여부로 미리 구분한다.
- 복수 출처 필요 여부: 여러 문서를 종합해야 하는지. 같은 문서의 여러 청크를 쓰는 경우와 구분한다.

정답을 문서·근거 위치로 연결해 두면 청크 크기를 바꿔도 같은 기준으로 비교할 수 있다. 청크 ID를 정답으로 지정하면 더 세밀하게 평가할 수 있지만, 재청킹할 때마다 정답 청크 ID가 바뀌어 평가셋도 갱신해야 한다. 필드 이름과 저장 형식은 평가 도구에 맞춘다.

## RAG Golden Set 질문과 기준 답변 작성 원칙
RAG Golden Set의 답변 가능 문항은 확인할 사실과 근거를 먼저 고르고, 그것을 묻는 질문과 기준 답변을 쓴다. 실제 사용자 질문이나 실패 사례에서 출발해도 원문 근거를 확인한다.
- 질문만 읽어도 무엇을 묻는지 알 수 있게 쓴다.
- 질문에 정답을 노출하지 않고 실제 사용자 표현을 쓴다.
- 기준 답변에는 조건·수치·예외를 넣고, 원문 밖 내용은 넣지 않는다.
- 사실 확인, 조건 비교, 여러 문서 종합, 비슷한 용어 구별 질문을 섞는다.
- 답변 불가 질문, 실제 사용자 질문, 기존 RAG가 틀린 질문도 넣는다.
- 같은 사실을 표현만 바꿔 반복하거나 특정 문서에 몰리지 않게 한다.

## RAG Golden Set 문항 작성 예시: 도서관 대출 안내
RAG Golden Set 예시는 가상의 문서 `library-guide`(버전 v1, "대출 기간과 연장" 절) 하나가 검색 대상 전부인 상황이다. 원문 요지: 일반 회원은 최대 3권을 14일간 빌리고, 예약자가 없는 도서는 1회 7일 연장할 수 있다.

답변 가능 문항 `loan-extension`:
- 질문: 일반 회원이 빌린 책은 어떤 조건에서 얼마나 연장되나? (구어체 변형 질문도 함께 둠)
- 기준 답변: 예약자가 없는 도서에 한해 1회, 7일 연장 가능
- 관련 문서 `["library-guide"]`, 근거 구절은 연장 문장, 답변 가능, 유형 사실 확인
- 예약자 유무·횟수·기간 세 가지가 모두 들어가야 한다.

답변 불가 문항 `overdue-fee`:
- 질문: 반납이 늦으면 연체료는 하루 얼마인가?
- 기준 답변: 문서에 연체료 정보가 없어 확인할 수 없다고 안내
- 관련 문서·근거 구절은 빈 목록, 유형 답변 불가
- 금액을 추측하거나 무료라고 단정하면 안 된다.

## RAG Golden Set 초안을 LLM으로 만들기
RAG Golden Set 초안은 LLM으로 만들 수 있다. 원문, 문서 ID, 질문 유형, 기존 질문 목록, 원하는 응답 항목을 함께 주고 프롬프트에 기준을 명시한다.
- 제공 원문으로 답할 수 있는 질문만 작성
- 질문은 단독으로 이해 가능하고 기존 질문과 같은 사실을 반복하지 않기
- 기준 답변에 원문에 없는 조건·수치 추가 금지
- 기준 답변의 모든 핵심 내용을 뒷받침하는 원문 구절을 그대로 인용
- 질문·기준 답변·근거를 구분해 반환

출처는 준비한 문서와 연결한다. 응답 형식을 고정해도 내용이 정확하다는 보장은 없으므로, 생성 결과는 초안일 뿐이고 원문 검수를 통과한 문항만 쓴다.

## RAG Golden Set 원문 대조 검수
RAG Golden Set 검수는 자동 검사와 사람 검수로 나눈다.
- 자동 검사: 유형별 필수 항목 누락, ID·질문 중복, 존재하지 않는 출처, 근거 구절이 원문에 실제로 포함되는지
- 사람 검수: 질문의 자연스러움, 답변의 정확성·완전성, 조건·예외 누락, 출처 누락, 의미상 중복

근거 구절이 원문에 있는지와, 그 근거가 기준 답변을 실제로 뒷받침하는지를 둘 다 본다. 수치·조건·적용 범위가 원문과 일치하는지도 확인한다. 관련 문서를 찾았어도 검색된 청크에 근거가 없을 수 있으니 "문서 일치"와 "근거 포함"을 구분한다. 오류 문항은 고치거나 빼고, 고친 문항은 다시 대조한다.

## RAG Golden Set 답변 불가 문항 구성
RAG Golden Set의 답변 가능 여부는 일부 청크가 아니라 평가 대상 원문 전체 기준으로 판단한다. 그래야 "검색기가 못 찾은 경우"와 "원문에 답이 없는 경우"를 구분할 수 있다.
- 기대 응답 방식을 적는다. 예: "제공된 문서로는 확인할 수 없습니다."
- 관련 문서와 근거 목록은 비워 두고, 없는 정답·근거를 만들어 넣지 않는다.
- 관련 문서가 빈 문항은 Recall@k 분모가 0이 되므로 해당 지표 평균에서 빼고, 제외한 수를 기록한다.
- 응답은 따로 평가해 근거 부족을 안내하는지, 없는 사실을 지어내지 않는지 본다.

## RAG Golden Set 개발셋·테스트셋 분리와 버전 관리
RAG Golden Set은 용도별로 나눈다.
- 개발셋: 청크 크기, 검색 방식, 프롬프트를 바꾸며 반복 비교할 때 사용
- 테스트셋: 개선 과정에 쓰지 않고 설정 확정 후 최종 성능 확인에만 사용

같은 문항만 보며 개선하면 그 문항에 과적합되므로 최종 확인용을 따로 둔다. 검수한 문항은 JSON·JSONL 등으로 저장하고, 원문 버전과 평가셋 버전을 함께 기록하며 작성 당시 원문도 보관한다. 질문·정답·근거가 바뀌면 새 버전으로 관리한다.

## RAG Golden Set을 RAG 평가에 연결하기
RAG Golden Set 평가에서는 질문을 RAG에 넣고 실제 검색 결과와 생성 답변을 기록한 뒤, 미리 준비한 기준과 비교한다.
- 미리 준비: 관련 문서 ID와 원문 근거, 기준 답변
- 실행 후 기록: 실제 검색한 문서·청크, 출처 ID, 검색 순위, RAG가 생성한 답변

기준 근거를 실제 검색 결과 대신 넣거나, 질문·정답 파일을 검색 대상 원문에 섞으면 안 된다. 비교에는 같은 버전의 Golden Set을 쓰고 평가 결과에도 그 버전을 기록한다.

## RAG Golden Set 복습 Q&A
- Q. RAG Golden Set의 기준 답변은 RAG 출력 문장을 그대로 맞히는 것인가?
  A. 아니다. 반드시 들어가야 할 핵심 내용과 조건을 정하는 것이며, 표현이 달라도 내용과 조건이 유지되면 된다.
- Q. RAG Golden Set에서 정답을 청크 ID로 지정할 때의 단점은?
  A. 재청킹할 때마다 청크 ID가 바뀌므로 평가셋을 매번 갱신해야 한다.
- Q. 답변 불가 문항은 Recall@k 계산에서 어떻게 처리하나?
  A. 관련 문서가 비어 분모가 0이므로 평균에서 제외하고 제외 수를 기록하며, 응답은 별도로 평가한다.
- Q. RAG Golden Set에서 개발셋과 테스트셋을 나누는 이유는?
  A. 같은 문항으로만 개선하면 그 문항에 맞춰지므로, 최종 성능은 개선에 쓰지 않은 테스트셋으로 확인하기 위해서다.
- Q. LLM으로 만든 Golden Set 문항은 바로 써도 되나?
  A. 아니다. 초안으로 취급하고 원문 대조 검수를 통과한 문항만 평가에 쓴다.
